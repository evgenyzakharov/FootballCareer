# Правила коммитов

Conventional Commits: заголовок по-английски, тело — по-русски. Заголовок читают
инструменты и `git log --oneline`, тело читает человек через полгода.

```
<тип>(<область>): <что сделано, в императиве, со строчной буквы>

<зачем это сделано и что важно знать; по-русски, строки до ~72 символов>

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

## Типы

| Тип | Когда |
|---|---|
| `feat` | новая механика, событие, экран |
| `fix` | исправление поведения, которое было неправильным |
| `balance` | правка чисел без правки логики: шансы, пороги, веса, тиры |
| `content` | новые тексты, локали, клубы, страны — без изменения механики |
| `refactor` | код переставлен, поведение то же |
| `test` | тесты и диагностические скрипты |
| `docs` | README, ARCHITECTURE, BACKLOG, комментарии |
| `chore` | зависимости, конфиги, tooling |
| `ci` | GitHub Actions и прочая автоматика |

`balance` и `content` выделены отдельно намеренно: в этом проекте правка одной
цифры в `ODDS` меняет ощущение от игры сильнее, чем рефакторинг на сто строк.
Такие коммиты надо уметь находить в истории.

## Области

По слоям и подсистемам, а не по файлам:

`engine`, `events`, `data`, `i18n`, `ui`, `save`, `balance`, `tests`, `docs`.

Область опускается, если правка сквозная.

## Заголовок

- Императив: `add`, `fix`, `move`, `drop` — не `added`, не `adding`.
- Со строчной буквы, без точки в конце.
- До 72 символов. Если не влезает — значит в коммите два изменения.
- Пишем **что сделано**, а не что затронуто: `fix: сбрасывать флаг wants_out
  в начале сезона` лучше, чем `fix: career.ts`.

## Тело

Тело обязательно, если ответ на «почему» не очевиден из заголовка. Что в нём
полезно:

- **Зачем.** «Флаг никогда не сбрасывался, поэтому окно открывалось каждое лето
  и игрок менял 14 клубов за карьеру.»
- **Замеренный эффект** для правок баланса — до и после, по `scripts/balance.ts`.
- **Что проверено.** Тесты, сборка, прогон интерфейса.
- **Осознанные компромиссы**, если они есть.

Чего в теле быть не должно: пересказа диффа построчно и списка затронутых файлов —
это уже есть в самом коммите.

## Примеры

```
feat(events): добавить арку возвращения после промаха в серии

Промах решающего пенальти теперь планирует redemption_arc на следующую
предсезонку. Без этого крупные события не имели продолжения и читались
как случайный шум.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

```
balance: сбрасывать желание уйти в начале сезона

Флаг wants_out выставлялся событиями и никогда не снимался, поэтому
marketIsOpen возвращал true каждое лето до конца карьеры.

По scripts/balance.ts на 80 карьерах: клубов за карьеру было 14.4 в
среднем, стало 9.3. Остальные показатели не сдвинулись.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

```
content(i18n): перевести ситуации со сборной на английский

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

## Что не коммитим

- `dist/`, `node_modules/` — в `.gitignore`.
- Инструментированные тестовые страницы (`dist/test.html`, `dist/dom-check.js`) —
  это одноразовые артефакты проверки, генерируются из `scripts/dom-check.js`.
- Сохранённые карьеры и профили браузера.

## Гигиена

- Один коммит — одно изменение. Правку баланса и новое событие не смешиваем:
  иначе непонятно, что именно сдвинуло цифры.
- Перед коммитом: `npm test && npm run lint && npm run build`. Все три обязаны
  быть зелёными — тест полноты локалей ловит забытые переводы, и это самая частая
  причина падения.
- Правки баланса подтверждаем прогоном `npx tsx scripts/balance.ts 80` и кладём
  числа в тело коммита.
- Ветка от `main`, `main` не коммитим напрямую, если работа не тривиальная.
- История не переписывается: вместо `--amend` и `push --force` — новый коммит.
